## 0. 需求原文拆解

1. 名字草案 → 存 localStorage；新增「意向吉名」卷插到卷六位（原卷六顺延为卷七）；
   每个意向名做完整 八字契合 / 平仄 / 五格 评估；另加 AI 对意向名的评价（流式）。
2. 吉名呈览（新卷七）候选卡加 like，like 即入意向吉名。
3. 卷七加模式切换「生成候选 | 名人吉名匹配」：从名人库按**名部**（不含姓）匹配，
   原名必须指出来源（真实出处，禁止伪造古籍引文）。

## 2. 意向存储 `src/utils/intent-names-storage.ts`（纯函数、注入式，仿 form-storage）

```
KEY = '问名手卷.意向吉名.v1'
IntentEntry = { 名: 汉字1-2串, 来源: '草案'|'点赞', 添加于: ISO字符串 }
loadIntentEntries(storage?)  → IntentEntry[]  // 永不 throw；无值/损坏/形状不符 → []；按名去重（保留最早添加于）；上限 60，超限裁最旧
```

## 3. 任意名评估 `POST /api/evaluate-names`

- 响应形状 = `src/lib/evaluate/types.ts` 的 `EvaluatedName[]`（已冻结，勿改）。
- 请求 zod（`src/lib/evaluate/schema.ts`）：
  `{ 姓氏(汉字1-2), 名字列表(1..30 项，各汉字1-2，项内去重), 喜用神(五行1-5), 忌神(五行0-5), 喜用神明细?(同 PoolInput 口径), 避讳字?(单字0-30) }`
- 实现 `src/lib/evaluate/evaluate.ts`：`evaluateNames(姓氏, 名单, ctx): EvaluatedName[]` 纯函数：
  - 逐字五行/声调/多音/表外 → `loadCharDB()`；表外字 → 记入 `表外字`（**只警告不过滤**，意向是用户的名字，评估如实呈报）。
  - 平仄 = orchestrate `buildDraftPingze` 口径（全名=姓氏+名；若该函数未 export，则 export 之或提公共 helper——只准加 export，禁改行为）。
  - 五格 = `computeWuge(姓氏, 名)`（可 null）。
  - 爆款度 = `buzzOfName`。
  - 契合分 = `charStaticScore` 的 喜/次/忌 三项之和（不含爆款/多音/常用级——那些是海选信号，不进展示分）；
    档位：全部字命中喜用(含次用)→'上'；有命中且无犯忌→'中上'；无命中无犯忌→'中'；犯忌→'下'。
  - 犯避讳 → `契合.说明` 加一条「含避讳字 X」，不隐藏不降档。
- 路由 `src/app/api/evaluate-names/route.ts`：抄 chart route 的 415/413/400/500 壳与文案风格；
  成功 `Response.json({ 评估 })`——即 `{ 评估: EvaluatedName[] }`。

## 4. 名人库 + 匹配

- 数据 `src/data/mingren-names.json`：`MingrenEntry[]`（形状见 `src/lib/mingren/types.ts`，已冻结）。
  目标 ≥150 条、去重（同 姓名 唯一）、名部 1-2 汉字；类别覆盖：文人/进士/艺术家/科学家/院士/企业家/政治家。
  **出处诚实**：史传/科第录 只写真实存在的书名（《宋史》《明清进士题名碑录索引》等）；
  当代人物一律 `出處類型:'公开资料'`，简介一句话事实（≤30 字），拿不准的宁可不收。
- 校验 `src/lib/mingren/data.test.ts`：zod 全量校验条目 + 名部正则 + 唯一性 + 条数下限 + 类别多样性。
- 匹配 `src/lib/mingren/match.ts`：`matchMingren(库: MingrenEntry[], req): MingrenCandidate[]` 纯函数（库由参数注入，路由负责读 JSON）：
  - 请求（`src/lib/mingren/schema.ts`）：`{ 姓氏, 性别, 名字形式(默认'双名'), 喜用神, 忌神, 喜用神明细?, 避讳字?, 禁用字?, 排除已选?, 上限?(默认20,max50) }`
  - 名部精确匹配 `名.长度 === 名字形式字数`；同名部多人生并一个候选的 `出處[]`。
  - 过滤链（对齐 pool 终筛口径）：含禁用字/避讳字 → 剔；表外字 → 剔（匹配是推荐场景，宁缺毋滥，与 §3 相反）；
    任一字五行∈忌神 → 剔；谐音黑名单命中 → 剔（复用现成 lib，若无 export 直读 xieyin-blacklist.json）；
    喜用命中 ≥1 字（主或次皆算）才留——全不中则宁缺毋滥剔除。
  - 评分排序复用 `charStaticScore` + `compareDraft`；`五格.评分.综合分 < 50` → 剔。
  - 每条 = `EvaluatedName` 形状 + `出處[]`（见 types.ts `MingrenCandidate`）。
- 路由 `src/app/api/mingren-match/route.ts`：同款 415/413/400/500 壳；成功 `{ 候選, 庫規模, 命中名數 }`。

## 修订 v2.1（2026-08-30）：批量导入 + 卷二名字加成

冻结正文不动，本节为增量契约（卷二加成 + 卷六批量导入两特性，用户拍板三项口径：
名字来源=卷六意向名单 / 加成建模=每字等权叠加段 / 导入方式=多行粘贴文本框）。

- `intent-names-storage.ts`：
  - `Intent来源` enum 扩宽为 `'草案' | '点赞' | '导入'`；存储 key 仍 `.v1` 不 bump
    （bump=清光用户名单）。兼容单向门：旧快照→新代码恒过；新快照→回滚旧代码时
    「导入」条目被 safeParse 静默过滤（影响面仅导入名自身、可重导、无崩溃）。
  - 导出 `HAN_NAME_PATTERN = /^[一-鿿]{1,2}$/`：名部合法性单一来源（schema 与导入解析共用）。
  - 新增 `addIntentEntries(名列表, 来源, storage?) => { 条目, 新增, 已存在, 满编丢弃 }`：
    不可变、批内去重保序、非法名静默跳过、**只填剩余容量丢尾部、既有 ≤60 条永不动**
    （与 addIntentEntry 的「规整裁最旧」刻意不同：导入是突发批量，裁旧=毁用户记忆）、单次写盘。
- 新增 `src/utils/parse-intent-import.ts`：
  `parseIntentImport(raw, 已有?) => { 有效名, 已在名单, 非法项 }`——
  `[、，,\s]+` 切「名」（顿号/全半角逗号/任意空白）；有效=HAN_NAME_PATTERN；
  **>2 汉字整项非法**（与 splitHanChars 按字拆分语义相反：导入以分隔符分「名」）；
  三桶去重保序；本层不做 60 截断（容量策略属存储层）。
- 评估状态上提：`src/components/use-name-evaluations.ts`（'use client' hook，
  逻辑自卷六逐行迁入；语义保真：chart=null 清态防重排盘闪旧评估、error 不清列表保「旧列表仍渲染」）。
  卷六/卷二共食同一 评估 状态（naming-app 持有，result-scroll 单向下发）。
- `src/utils/name-bonus.ts`：`计算名字加成(五行力量, 选中)` 纯建模——选中名逐字五行
  每字 +1 单位（`单位刻度=4`，每单位=力量条轨道 4%，常量不随 maxScore 浮动），
  基准得分不动；分类=元素级查契合命中（喜/次/忌/无）；
  `雷达刻度 = max(基准max, 加成后max)` 供雷达双多边形共享分母（否则对比说谎）。
- `radar.ts`：`RadarOptions.maxValue?`——给定替代 `max(values,1)` 做归一分母，未给定行为逐字节不变。

## 修订 v2.2（2026-08-30）：送评上限 30 → 100

用户拍板：卷六 AI 点评「名单较长，仅送评前 30 个」碍事，上限放宽到 100。

- `EVALUATE_NAMES_MAX = 30` → `100`（`src/lib/evaluate/types.ts` 单一事实源，消费方零改动）：
  - `/api/evaluate-names` 请求 `名字列表` 上限（正文 §4「1..30 项」以本节为准）、
    前端切片步长（use-name-evaluations）、`/api/analyze-names` 请求 `评估` 上限（正文 §5「≤30」同）、
    卷六「仅送评前 N 个」提示文案——全部随常量走。
  - 效果：意向名单满编 60 ≤ 100，一程送评不再截断，提示自然不再出现（常量保留作纵深防御）。
- 兼容性：放宽为纯扩界，旧客户端 ≤30 请求恒过；无存储形状变化。
